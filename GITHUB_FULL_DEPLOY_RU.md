# Полная сборка GitHub Pages — v05.10 RC: единый редактор и тестовые арты

Архив `MW_Mythical_Wars_v2.1M.2_v05.10_GitHub_FULL_BATTLE_CARDS_FIX.zip` — **полный автономный репозиторий**, а не обновление отдельных файлов.

## Публикация

1. Распакуйте ZIP; откройте папку `mythical-wars`.
2. Перенесите **всё содержимое папки**, включая скрытую `.github/`, в корень репозитория, где расположен `index.html`. Учитывайте, что папка `test-art/` содержит **99 default WebP plus 7 archived previous versions** и необходима на сайте целиком.
3. Для существующего репозитория сохраните резервную копию перед заменой файлов. Для нового: `git init -b main`, добавьте remote и выполните `git add .`, `git commit -m "MW v05.10 RC: one editor and default test art"`, `git push -u origin main`.
4. В GitHub **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. В **Actions → Publish Mythical Wars to GitHub Pages → Run workflow** запустите публикацию.
6. Проверьте открытие главной страницы, коллекции и `v05-dynamic.html`. Старого редактора и лаборатории шаблонов v05-studio в меню быть не должно.

Сборка `tools/build_pages.py` включает `test-art/`, исходные `v05/` ассеты, библиотеку и клиентские скрипты. `v05-studio.html` **исключается** из статического артефакта; её QA-исходник оставлен в репозитории.

## Проверка перед публикацией

```bash
node --test
python3 tools/check_static_site.py
python3 tools/build_pages.py
python3 tools/check_static_site.py --root _site
```

Для локальной визуальной проверки запустите в отдельном терминале `python3 -m http.server 8765` и откройте `http://127.0.0.1:8765/` и `http://127.0.0.1:8765/v05-dynamic.html`.

Пройдите сценарий: коллекция → CHR-001 → открыть в v05; KNZ-001 и NEU-023 должны автоматически показывать **свои** тестовые арты. KNZ-019/006/014 используют оригинальный источник v05; артов у остальных 70 записей нет (смотрите отчёт). Пользовательский арт и кадрирование не должны пропадать после переключения карты. Проверьте фильтр «Только карты со встроенным артом», затем замените арт CHR-001 и нажмите «Вернуть встроенный арт»: стандартный файл должен восстановиться без сброса кадрирования. PNG неутверждённых токенов остаётся заблокированным.

## Безопасность и ограничения

Это клиентский GitHub Pages сайт; **синхронизация с приватной Google Sheets требует отдельного HTTPS backend** и недоступна без него. Не загружайте service account JSON, `.env`, приватные ключи. GitHub Pages и локальный сайт не делят браузерное хранилище: прежде чем сменить домен или адрес, сохраните резервные JSON и арты.

Это **v05.10 RC**, не объявленный стабильным релизом. Автоматический Chromium QA проводился на `about:blank` с исходными PNG/WebP через Blob URL, а не на опубликованном GitHub. Перед публикацией всех артов подтвердите права на распространение.


## Дополнительно v05.10 — бой / 2D / начальная замена / 3D

После загрузки/обновления очистите кеш страницы (Ctrl+Shift+R) и проверьте:

1. Начните новый бой Воин vs Воин и убедитесь, что у всех видимых карт единое оформление v05.
2. На начальной замене должны быть **лица** карт (не только рубашки и названия); монетка не заменяется.
3. Откройте карту KNZ-019 крупно: текст на ленте светлый, стоимость/атака/здоровье по центрам значков.
4. После начала боя откройте 3D и подождите загрузки изображений. Сначала разрешена подпись «Загрузка лицевой стороны…», после — тот же v05-шаблон.
5. Если 3D не обновляется, сделайте Ctrl+Shift+R, сохраните экспорт боя JSON, пришлите консоль браузера. 3D WebGL не прошёл реальную приёмку на Windows и опубликованном Pages в среде сборки.

Боевые правила и карты не менялись. 99 встроенных тестовых изображений остаются; 70 отсутствуют — для них явно написано «АРТ В РАЗРАБОТКЕ».
