# MW — T03. Контракт событий и очередь, инкремент 1

16.11.2026. Базовый commit: 1b88856d94817d394ab33ededfddb2dea4995124.

## Объём и статус

Реализована первая поставка второго этапа: командная граница, типизированные события для простого розыгрыша, отдельная публичная проекция состояния и последовательная очередь с восстановлением после ошибки VFX. В UI подключён розыгрыш существа без ability/keywords через клик и существующий DnD-путь. Первый реальный пример — KNZ-002 МАЛАДЫ ДРУЖЫННІК.

Это не закрывает T03/AN-15 полностью: все действия, одновременные цепочки, обязательные выборы, таймер и полноценное отдельное представление существующих 2D/3D-рендереров ещё не переведены. T04 полного хода также не закрыт. Остальные игровые пути сохраняют прежнее исполнение. Такой объём следует декомпозиции T01: сначала доказать границу и один сценарий, затем подключать дополнительные события.

Не изменены: battle-engine.js, правила, библиотека карт, баланс, RNG и формат сохранений/повторов. Подключение battle-presentation.js идёт после battle-replay.js, поэтому принятая команда по-прежнему записывается существующим replay. Техническая схема — реализация для текущего прототипа, не новое игровое правило.

## API

UMD-модуль `battle-presentation.js`: browser `MW_BATTLE_PRESENTATION`, Node `require`.

- `createSession(engine, game, {battleId, viewer=0, limit=1024})`: создаёт границу команд вокруг существующего ядра. Session и её дедупликация живут только в текущем сеансе представления; это не серверная идемпотентность.
- `execute({commandId, type, args, expectedRevision})`: вызывает разрешённый публичный метод ядра один раз. Повтор того же ID с тем же payload возвращает копию сохранённого результата; другой payload отвергается. Устаревшая revision отвергается. Отказ ядра не создаёт успешную сцену и не повышает revision.
- Разрешены playCard, attack, useHeroPower, endTurn, confirmMulligan. Для методов, кроме подключённого простого розыгрыша, доступно подтверждение результата через stateCommitted; детальные боевые события ещё не инструментированы и методы не подключены к UI-очереди.
- `publicView(game, viewer)`: создаёт независимый viewer snapshot. В нём нет порядка колод, UID/лиц скрытой руки соперника, RNG, replay, исходных logs и приватных discoveryOffers. Локальная рука и видимое поле адресуются UID. Это ещё не полный сетевой протокол приватности всех игровых механик.
- `createProjection({battleId, view, revision})`: держит отдельный снимок, меняет его только на stateCommitted, игнорирует повтор/другую партию/старую revision, отвергает пропуск commit-revision. Возвращает копию view.
- `createQueue({handle, apply, onError, timeoutMs=2500, limit=20000})`: последовательно проигрывает события. Каждое имеет deadline и AbortSignal. Ошибка/таймаут сцены не отменяют принятый результат ядра. Apply выполняется и после ошибки VFX. reset отменяет активную сцену и блокирует применение старого поколения.

Схема события v1:

| Поле | Значение |
|---|---|
| schemaVersion | 1 |
| battleId / revision / eventId | Пространство партии, версия принятой команды, уникальный ID события |
| commandId / parentEventId | Связь с командой и корневым принятием |
| sourceInstanceId / targetInstanceIds | UID сыгранной карты и созданного существа, не cardId |
| batchId | Группа команды; **не** утверждение одновременности всех её последствий |
| viewer / visibility | Адресат публичного снимка; разыгранная карта раскрыта, скрытый добор не раскрывается |
| blocking | Барьер текущей сцены |
| type / payload | Структурированные данные, без разбора текста исторического журнала |

Для принятого простого существа:

1. commandAccepted.
2. cardPlayDeclared: UID карты руки, cardId и разрешённая лицевая сторона.
3. creatureSummoned: UID единственного нового совпадающего существа и индекс.
4. stateCommitted: публичные before/after.
5. commandResolved.

Если эффект даёт более сложный результат, не выдумываются промежуточные damage/death/choice-события из net-diff: остаётся stateCommitted до отдельной инструментализации ядра. batchId недостаточен для одновременной массовой гибели — будущим событиям требуется simultaneityGroup в надлежащих точках расчёта.

## UI и восстановление

`deckgame.js` направляет человеческие пути playCard через общий helper. Простой розыгрыш использует session; остальные карты идут по прежнему пути. Сначала ядро принимает команду и сохраняется её результат, затем показывается нейтральная временная копия карты (подъём 48px, 260мс), после чего обновляется поле. Это диагностическая подача, а не утверждённая финальная траектория превращения карты в овал.

Во время сцены блокируются клики/клавиши/drag/drop рабочего поля, окончание хода и команды bridge. Повторный render не уничтожает исходный DOM до stateCommitted. После сцены управление возвращается; при отсутствии Web Animations/при reduced motion результат применяется без ожидания движения.

При скрытии вкладки очередь отменяется и экран достраивается по уже принятому состоянию. При новом бое/загрузке сбрасывается поколение, старые callbacks не применяют результат в новой партии. Сохранение содержит только существующее игровое состояние; визуальная сцена после загрузки не повторяет оплату или RNG. Обязательный незавершённый выбор пока не входит в подключённый сценарий; эта гарантия на него не распространяется.

Лимит истории не вытесняет старые ID молча: переполнение отвергается. После исключения внутри ядра session блокирует дальнейшие команды и предлагает восстановить принятый save; повтор ID не запускает ошибочную команду второй раз. Это не механизм отката частично упавшего ядра.

Проекция держит UID и промежуточный подтверждённый снимок отдельно от расчёта. Основной renderer пока обновляет DOM прежним способом в точке commit. Стабильные DOM-узлы/FLIP и полное переключение 3D на проекцию остаются следующей частью T03.3/T09, не выдаются за выполненные.

## Проверки

- Полный Node-набор: 199/199 PASS, 0 fail, 0 skipped.
- 12 новых проверок: однократная оплата; порядок причина→призыв; replay; отказ/устаревшая revision; коллизии ID/лимиты; скрытые данные; проекция/UID; сериализация/дедуп очереди; таймаут/исключение VFX; отмена поколения; проверка всего batch; ошибка ядра без повторного вызова; одинаковый итог с анимацией/без и загрузка принятого save; две копии одной карты различимы. Некоторые проверки объединяют несколько названных случаев в одном тесте.
- Pages static build: 577 файлов. Проверка 376 HTML/CSS/manifest ссылок PASS, исходный manifest сохранён.
- Chrome на локальном preview: старт Воин/Воин, муллиган; через существующий режим разработчика в тестовую руку выдан KNZ-002 без изменения каталога. Во время розыгрыша наблюдались aria-busy=true, одна временная копия, старый пустой ряд. После завершения: aria-busy снят, ghost=0, одно существо, 4 карты в руке вместо5, мана0/1 вместо1/1, кнопка завершения доступна.
- После browser smoke добавлены защита от исключения ядра и дополнительные Node-проверки; они прошли в итоговом наборе. Повторный browser smoke именно этой последней защиты не выполнялся; нормальный путь UI не менялся.
- Полная Q13/Q15, живая 3D-сессия, touch, все браузеры и FPS не проверены. Новая публичная версия не развёрнута.
