## Технические границы

- `battle-hand-motion.js/.css` — геометрия промежутков/захвата, полёты, FLIP, стартовая подача, очистка. Все полёты используют экранные координаты, без повторного применения масштаба арены.
- `battle-hand-v05S14.js` — стабильное превью и точка захвата. Приоритет старого battlefield CSS исправлен отдельным правилом для фактического #myHand. Прежние вспомогательные функции геометрии оставлены совместимыми.
- `battle-engine.js` — совместимый шестой аргумент playCard: position, по умолчанию null/добавление справа. Индекс проверяется до оплаты. Только прямой розыгрыш использует выбранное место; порядок остальных призывов сохранён.
- Наблюдение за добавлением в руку хранится во внешнем WeakMap. В save/replay snapshot не появляются новые служебные массивы, UID и RNG создаются прежним кодом. Переполнение и усталость не рисуют фиктивную карту.
- `battle-presentation.js` — причинные события движения и сохранение выбранной позиции в sidecar выбора. Повтор commandId не вызывает повторную оплату. Скрытые события не содержат чужих hand UID/cardId/card.
- `deckgame.js` — соединение с рабочим боем игрока/ИИ, сохранением и очередью. Рендер accepted state выполняется один раз логически; анимация не вызывает команды ядра. Ввод блокируется на время принятого действия. В 3D используется прежний рендер без этих 2D-полётов; новые placement controls туда не переносились.
- Есть быстрый путь для reduced motion/скрытой вкладки и восстановление при сбросе очереди/таймауте. Полную проверку всех сочетаний resize/background/load/failure проводить на этапах 8–9.

## Что не объявляется закрытым

Это реализация этапа 5 с функциональной проверкой, не окончательная приёмка всей Q01–Q15. В браузере не пройдена полная матрица рук 1/3/7/10 и всех заполнений поля 0–7, мобильных устройств, touch, других браузеров, live 3D и FPS. Три последовательных добора и старт вторым с монеткой проверены на уровне ядра/событий, не отдельным полным browser-сценарием. Неподдерживаемые эффекты карт не расширялись. Спорные игровые вопросы и найденные ранее overkill/checkEnd/timeMode/hitbox этим этапом не исправляются автоматически.

D03 — точное начало/сброс/восстановление светящихся точек часов — остаётся открытым. D04 — финальный темп/стиль — требует визуальной приёмки. D05 — целевые устройства — открыт.
