# Встроенные арты v05.8 — руководство

## Где находятся арты

92 тестовых изображения упакованы в `test-art/{ID}.webp` и доступны непосредственно в составе игры, без подключения Google Drive или другого CDN. `mw-test-art-catalog.js` отображает ID в путь; данные об источнике, checksum и статусе записаны в `test-art/test_art_inventory.json`. На опубликованном GitHub Pages эти файлы раздаются с того же домена, что и приложение.

Назначение происходит **только** по точному ID. Внутри шаблона v05 иллюстрация накладывается по собственной маске. Файлы v05-манифеста, слои, текст, параметры карты и правила игры автоматически не изменяются.

## Порядок использования

1. Откройте `v05-dynamic.html` через локальный веб-сервер или GitHub Pages.
2. Выберите карту из локальной библиотеки. При желании включите «Только карты со встроенным артом».
3. Справа увидите миниатюру встроенного изображения и отметку «тестовый, не утверждён».
4. Если для этой карты есть собственная локальная замена, кнопка «Вернуть встроенный арт» восстановит исходный WebP и очистит локальную замену для этого ID. Положение и масштаб остаются прежними; отдельная кнопка «Сбросить кадрирование» сбрасывает только кадрирование.
5. Экспорт PNG возможен, только если у карты нет блокирующих ошибок шаблона/данных.

При первой загрузке карты встроенный арт используется по умолчанию, **если нет сохранённой пользовательской замены**. Никакая запись в рабочую Google-таблицу не выполняется.

## Нет изображения

Для 70 обычных карт и 7 токенов валидный исходный арт отсутствует. Редактор честно сообщает об этом и не подбирает другой по классу. Чтобы добавить дополнительные **встроенные** изображения, нужны отдельные исходные PNG/JPEG/WebP и достоверное соответствие ID. Перед новым выпуском должны быть обновлены `test-art/`, инвентарь с SHA-256, `mw-test-art-catalog.js` и проверка покрытия. Не следует придумывать или повторно использовать арт другой карты.

## Контрольные карты

KNZ-019/KNZ-006/KNZ-014 продолжают использовать оригинальные источники `v05/{ID}/{ID}_art_source.png` при первом открытии, чтобы не нарушить контрольные примеры. У них также есть отдельные WebP-копии в `test-art/` для инвентаризации.

## Хранение и безопасность

- Встроенные изображения — статические файлы проекта; сам редактор не изменяет их при замене пользовательского арта.
- Пользовательские арт и crop сохраняются в браузере (IndexedDB) только для конкретного ID. Очистка данных сайта может удалить личную замену, но встроенные арты останутся в поставке.
- При переезде с `127.0.0.1` на GitHub Pages браузерное IndexedDB не переносится автоматически.
- Арты имеют тестовый статус, не являются утверждёнными и перед публикацией должны иметь разрешение на распространение.
